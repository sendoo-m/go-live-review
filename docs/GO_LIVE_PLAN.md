## 1. محاور التحقق الإلزامية ليوم الإطلاق (Launch Day 9 Pillars)

```
┌────────────────────────────────────────────────────────────────────────┐
│               محاور الجاهزية التشغيلية التسعة ليوم الإطلاق             │
└────────────────────────────────────────────────────────────────────────┘
  [1] الحزم الموقعة النهائية       [2] بيانات ووثائق المتاجر       [3] جاهزية الخادم (API v2)
  [4] سحابة Cloudflare R2         [5] تقارير الأعطال والسجلات    [6] منصات التحليلات
  [7] أصول ووسائط التطبيقات        [8] بريد الدعم sendoo.m@gmail   [9] مسؤول الـ Hotfix والمناوبة
```

| المحور | معيار التحقق | الحالة |
| :--- | :--- | :---: |
| **1. الحزم النهائية (Signed Artifacts)** | بناء `app-release.aab` بتوقيع الإنتاج و R8 Obfuscation مع ملف `symbols.zip`. وبناء `ipa` موقع بشهادة Apple Distribution. | 🟢 مكتمل |
| **2. بيانات وصفحات المتجر** | ضبط الأوصاف، الكلمات المفتاحية، لقطات الشاشة، وروابط الموقع الرسمي (`https://dalilaykhidma.com/`). | 🟢 مكتمل |
| **3. جاهزية خادم الباك إند (Backend)** | استقرار نقاط النهاية `/api/v2/*`، تشغيل حماية CORS ومعدل الطلبات (Rate Limiter)، وفحص صحة قاعدة البيانات. | 🟢 مكتمل |
| **4. سحابة Cloudflare R2** | تفعيل الدومين المخصص `https://images.dalilaykhidma.com` واختبار الرفع والتنزيل وحصص التخزين. | 🟢 مكتمل |
| **5. نظام تقارير الأعطال (Crash Reporting)** | تفعيل حجب البيانات الحساسة (PII Masking) والتقاط الـ Breadcrumbs وربط Sentry/Crashlytics. | 🟢 مكتمل |
| **6. لوحة التحليلات (Analytics)** | التحقق من تدفق أحداث `screen_view`, `search_performed`, `activity_viewed`, و `inquiry_created`. | 🟢 مكتمل |
| **7. الأصول والوسائط المدمجة** | التأكد من عمل أيقونات التطبيق، شاشات البداية (Splash Screens)، والتوافق مع شاشات Retina / High DPI. | 🟢 مكتمل |
| **8. قنوات الدعم والتواصل** | جاهزية صندوق البريد المعتمد `sendoo.m@gmail.com` وقناة الواتساب للمساعدة الفورية. | 🟢 مكتمل |
| **9. فريق الطوارئ (On-Call Owner)** | تعيين مسؤول تقني مباشر لمتابعة الساعات الأولى من الإطلاق وتنفيذ أي Hotfix طارئ. | 🟢 مكتمل |

## 2. الجدول الزمني التشغيلي ليوم الإطلاق (Launch Day Timeline)

### المرحلة الأولى: ما قبل الإطلاق (T-2 Hours):
- [ ] إجراء فحص نهائي لنقاط الاتصال بالخادم:
  ```bash
  curl -I https://dalilaykhidma.com/api/v2/activities
  curl -I https://images.dalilaykhidma.com/
  ```
- [ ] التحقق من صلاحية شهادات SSL لجميع النطاقات الفرعية.
- [ ] التأكد من توفر حسابات المراجعة التجريبية في قاعدة البيانات.

### المرحلة الثانية: لحظة الإطلاق (T-0 Launch Execution):
- [ ] **Google Play Console:**
  - الانتقال إلى مسار Production.
  - تحديد نسبة الإطلاق الأولي: **10% Staged Rollout**.
  - الضغط على **Start Rollout to Production**.
- [ ] **App Store Connect:**
  - اعتماد إصدار الإنتاج والموافقة على النشر.
  - تفعيل **Phased Release for Automatic Updates** (يبدأ بـ 1%).

### المرحلة الثالثة: الساعات الأولى للمراقبة (T+1 to T+4 Hours):
- [ ] مراقبة لوحة الأعطال كل 15 دقيقة للتأكد من بقاء معدل الأعطال عند `0%`.
- [ ] فحص سجلات الخادم للتحقق من استجابة استعلامات البحث وتوليد الروابط الموقعة لـ R2.
- [ ] مراقبة وارد صندوق البريد `sendoo.m@gmail.com`.

### المرحلة الرابعة: تقييم نهاية اليوم الأول (T+24 Hours):
- [ ] إعداد ملخص الاستقرار اليومي (Daily Stability Digest).
- [ ] مراجعة قرار زيادة نسبة الطرح إلى **25%** في حال اجتياز جميع المعايير.
