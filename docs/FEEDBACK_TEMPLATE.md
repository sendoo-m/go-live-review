## 1. قنوات جمع الملاحظات المعتمدة (Feedback Channels)
1. **أداة TestFlight المدمجة (iOS):** التقاط لقطة شاشة والضغط على زر المشاركة لاقتراح الملاحظة أو التبليغ عن خطأ تلقائياً مع تفاصيل النظام.
2. **بريد الدعم والملاحظات المعتمد:** `sendoo.m@gmail.com` (مربوط بلوحة التذاكر المباشرة).
3. **قناة تليجرام / واتساب خاصة بالمختبرين والتجار:** للتواصل اللحظي وحل الاستفسارات السريعة.
4. **شاشة "إرسال ملاحظة" داخل التطبيق:** تتيح للمختبر تدوين ملاحظته وتحديد نوعها مع إرفاق المعرف التقني للجلسة تلقائياً.

## 2. مصفوفة تصنيف الملاحظات والأعطال (Severity Classification Matrix)

| التصنيف (Severity) | التعريف والأثر | زمن الاستجابة المستهدف | هل يمنع الإطلاق العام؟ | أمثلة توضيحية |
| :--- | :--- | :--- | :---: | :--- |
| 🔴 **P0 - Blocker** | عطل يمنع استكمال رحلة حيوية، انهيار كامل للتطبيق (Crash)، فشل حفظ البيانات، أو عدم إمكانية تسجيل الدخول. | إصلاح فوري خلال **< 12 ساعة** | **نعم (Blocking)** | انهيار عند فتح الخريطة، فشل حفظ منتج جديد، أو عدم القدرة على فتح النشاط. |
| 🟡 **P1 - Warning / Major** | خلل وظيفي جزئي يوجد له حل بديل، بطء ملحوظ في استرجاع الصور، أو خطأ في معالجة الروابط العميقة. | إصلاح خلال **24 - 48 ساعة** | **مشروط** (حسب التأثير) | تأخر ظهور نتائج البحث عند ضعف الشبكة، أو عدم فتح رابط الواتساب على بعض الأجهزة القديمة. |
| 🟢 **P2 - Minor / UX Polish** | ملاحظات تحسين في الواجهات، تناسق هوامش، تحسين صياغة نص عربي، أو إضافة تلميح مساعد. | ضمن التحديث القادم | **لا (Non-blocking)** | تعديل حجم خط العنوان، تحسين نص زر معين، أو إضافة فراغ إضافي أسفل القائمة. |

## 3. نموذج الإبلاغ عن مشكلة (Standard Bug Report Template)

```markdown
### 📝 تقرير ملاحظة اختبار تجريبي (Beta Bug Report)

- **التطبيق:** [ ] تطبيق المستخدم (`user_app`)  |  [ ] تطبيق التاجر (`merchant_app`)
- **رقم الإصدار و Build Number:** مثال: `1.0.0 (Build 1)`
- **نوع الجهاز ونظام التشغيل:** مثال: `Samsung Galaxy S23 - Android 14` أو `iPhone 14 Pro - iOS 17.4`
- **التصنيف:** [ ] P0 - Blocker  |  [ ] P1 - Warning  |  [ ] P2 - Minor

#### 1. عنوان المشكلة (Short Summary):
> مثال: فشل رفع صورة المنتج عند استخدام صور عالية الدقة أكبر من 5MB.

#### 2. خطوات تكرار المشكلة (Steps to Reproduce):
1. تسجيل الدخول بحساب التاجر التجريبي.
2. التوجه إلى تبويب "الكتالوج" ثم الضغط على "إضافة منتج".
3. اختيار صورة من المعرض بحجم 6MB والضغط على "حفظ".

#### 3. السلوك الفعلي الملاحظ (Actual Result):
> يظهر شريط التحميل ثم تتوقف العملية وتظهر رسالة "حدث خطأ أثناء الرفع".

#### 4. السلوك المتوقع (Expected Result):
> يتم ضغط الصورة تلقائياً ورفعها إلى Cloudflare R2 بنجاح وإغلاق النموذج.

#### 5. المرفقات (Screenshots / Screen Recording / Crash Logs):
> [إرفاق صورة أو فيديو يوضح المشكلة]
```

## 4. استبيان تقييم تجربة المختبر (Tester Experience Survey Checklist)

### أ. لمختبري تطبيق المستخدم (`user_app`):
- [ ] هل تجربة البحث والوصول للنشاط كانت سريعة وواضحة؟
- [ ] هل واجهت أي بطء أثناء استعراض الخريطة أو التمرير في الكتالوج؟
- [ ] هل أزرار الاتصال والمراسلة المباشرة عبر واتساب عملت بدقة ومن أول ضغطة؟
- [ ] هل النصوص العربية والخطوط مريحة للعين في الإضاءة النهارية والليلة؟

### ب. لمختبري بوابة التاجر (`merchant_app`):
- [ ] هل كانت إدارة الكتالوج وإضافة الأسعار والصور واضحة وسريعة؟
- [ ] هل استقبلت إشعارات الاستفسارات الجديدة دون تأخير؟
- [ ] هل مسار الـ CRM ومتابعة العملاء عبر واتساب ساعدك في إدارة الطلبات؟
- [ ] هل واجهت أي صعوبة في قراءة إحصائيات المشاهدات والزيارات؟
